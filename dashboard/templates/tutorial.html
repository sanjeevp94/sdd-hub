Spec Kit Onboarding Tutorial

Welcome to the Multi-repo Spec-Driven Development Hub! This tutorial walks you through the 8-phase Spec Kit lifecycle. Open your agent (e.g., Claude Code) in the specs/ directory and follow along.

Phase 1: Foundation

1. Constitution

Run /speckit.constitution to establish project principles, architectural guidelines, and standard coding practices. This creates the rules your agent will follow.

2. Specify

Run /speckit.specify [feature idea] to write the feature specification. This describes the WHAT and WHY of the feature.

3. Clarify (Optional but Recommended)

Run /speckit.clarify. The agent will ask structured questions to resolve ambiguities in your spec before planning.

Phase 2: Planning & Tasks

4. Plan

Run /speckit.plan to create the technical implementation plan. This defines HOW the feature will be built technically.

5. Checklist

Run /speckit.checklist to generate a quality validation checklist to ensure requirements completeness.

6. Tasks

Run /speckit.tasks to break the plan down into a dependency-ordered task list.

Phase 3: Execution

7. Analyze

Run /speckit.analyze to perform a cross-artifact validation to ensure the spec, plan, and tasks are all perfectly aligned.

8. Implement

Run /speckit.implement to execute the tasks sequentially with test gates. This is where the code gets written!

Extensions Included

This workspace also includes custom extensions. You can run commands like:

  • /speckit.retrospective.analyze - For sprint retrospective analysis.
  • /speckit.coding-standards-drift-control.report - For checking coding standard drift.
  • /speckit.wiki.init & /speckit.wiki.ingest - For compounding project wiki management.
  • /speckit.bdd.scenarios - For generating BDD Gherkin files from specs.
  • /speckit.ship.run - Automates the release pipeline, changelog, and PR verification.
